문제2: B마트 재고 API 테스트 자동화 구현 (코드 필수)
배경
ᄂ B마트는 배달의민족이 운영하는 장보기 서비스입니다.
ᄂ 실시간 재고 관리가 핵심이며, 피크 타임에는 동일 상품에 대한 동시 주문이 빈번하게 발생합니다.
ᄂ 재고 차감과 주문 처리 사이의 데이터 정합성이 서비스 신뢰도와 직결됩니다.
재고 처리 규칙
이벤트 재고 변동 고객 화면 처리 비고
고객이 장바구니에 상품 추가 변동 없음 (조회만) 현재 재고 수량 노출 장바구니 담는 시점에는 재고 차감 없음

주문 결제 완료 주문 수량만큼 즉시 차감 주문 완료 화면 동시 주문 충돌 시 선착순 처리. 이후 요청은 품절 처리
주문 취소 (결제 완료 후) 차감된 재고 즉시 복구 취소 완료 알림 복구 후 다른 고객이 즉시 구매 가능 상태 전환
재고 차감 후 수량 = 0 해당 상품 품절 전환 "품절" 배지 표시, 주문 버튼 비활성화 다른 탭에서 조회 중인 고객에게도 즉시 반영되어야 함
운영자가 재고 수동 수정 입력값으로 즉시 반영 실시간 업데이트 수정 중 주문 발생 시 처리 순서 정의 필요
동시성 시나리오
ᄂ 특정 인기 상품의 재고가 마지막 1개 남았습니다.
이때 고객 A와 고객 B가 거의 동시에 해당 상품을 결제합니다.
두 결제 요청이 서버에 수십 밀리초 간격으로 도달합니다
테스트 케이스 설계
ᄂ 아래 가상의 API가 있다고 가정하고(명세는 지원자가 합리적으로 정의), 테스트 자동화 코드를 작성해주세요.
ᄂ GET /v1/products/{productId}/stock — 재고 조회
ᄂ POST /v1/orders — 주문 생성(재고 차감)
ᄂ POST /v1/orders/{orderId}/cancel — 주문 취소(재고 복구)
요구사항
ᄂ 정상 케이스, 재고 복구, 품절 전환을 포함한 API 자동화 테스트 코드 10개 이상 작성
ᄂ 재고 1개 남은 상품에 두 요청이 수십 ms 간격으로 도달하는 동시성 테스트를 코드로 구현 (병렬 요청 → 1건 성공/1건 품절 검증)
ᄂ 실제 서버가 없으므로 Mock 서버(WireMock, responses 등) 또는 직접 구현한 간단한 스텁 서버를 사용해 실행 가능한 상태로 제출
ᄂ 테스트 코드의 구조 설계(fixture, 데이터 준비, 검증 헬퍼 등)에 대한 설명을 README에 포함
